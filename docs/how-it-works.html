AI Job Search, explained.

There is no agent code. Claude Code is the agent, the markdown files are the implementation, and the only programs are deterministic: portal clients, PDF checks and a few Python helpers. This page shows how a posting travels from a job board to a compiled, verified application.

01 · The parts

Four kinds of things, two of them prose.

Skills and commands are markdown Claude reads. Portal CLIs and helper tools are code Claude runs. Nothing in the repository calls a model.

.claude/skills/*/

Skills

Knowledge and procedure. The core one is nine numbered files: profile, behavioral profile, writing style, the scoring framework, CV and letter templates, interview prep, portal forms, web-research rules. Loaded when a task matches the description.

Claude reads
.claude/commands/*.md

Commands

Numbered scripts. Typing /apply makes Claude read apply.md and follow its steps in order, reading each reference file exactly once.

Claude reads
.agents/skills/*/cli/

Portal CLIs

Bun and TypeScript clients, one per job board, with search and detail subcommands and JSON output. Jobindex, Jobnet, Jobbank, Jobdanmark, LinkedIn, Freehire. Each ships its own flag reference so nothing is guessed.

Claude runs
tools/*.py

Helper tools

Stable job keys, seen-jobs queries and writes, PDF page and text-layer checks, layout measurement, a robots.txt gate. Deterministic, tested in CI.

02 · The pipeline

Six commands, one loop.

Setup builds the profile. Scrape finds postings. Rank triages them. Apply produces one application. Outcome records what happened, and interview prepares the next round. Resolved outcomes feed back into the scoring framework.

- - - calibration loop
/scrape

Discovers every enabled portal skill, translates the saved queries into that portal's flags, scopes to 14 days, runs the CLIs in parallel through sub-agents, drops anything already seen or tracked, and assigns high, medium or low. A required language the profile never declares forces low.

/rank

Never loads the seen-jobs file into the conversation. A Python query picks ten candidates; sub-agents fetch and score five each and return JSON; the main session weights, vetoes, flags urgency and staleness, then writes back through the same tool. Triage only: apply always re-evaluates.

/outcome · /interview

Outcome records stages and results, drafts follow-ups after ten quiet days using only submitted claims, and sweeps sixty-day silence. Interview preps from what the interviewer actually read, verifies every company fact, and runs a mock coached toward your natural register.

03 · Inside /apply

One session drafts. A second one, with no memory of the first, critiques.

The reviewer is spawned with the drafts pasted inline and a fresh context, so it cannot see or rationalize the drafter's choices. It returns exact string edits the drafter applies without re-reading a file.

The standing rule above every step. Any fact you state in chat that is not yet in the profile is written to 01-candidate-profile.md in the same turn. Claude forgets everything between sessions, and the next session's grounding audit strips an unsourced claim as a fabrication. A real achievement that lives only in a conversation disappears silently from every later CV.

05 · The scoring framework

Two gates, then four weights and a pass/fail.

Gates are hard filters that run before any number is produced. A posting that fails one is not scored and not drafted; the exact wording is quoted back to you.

Eligibility gate

A stated citizenship, residency or clearance requirement you cannot meet fails the posting. Silence is not permission: it is marked unverified and checked on the employer's own site. A company-wide "international applicants welcome" is not role-level permission.

Language gate

A required language your profile does not list fails. A listed language at a bar that reads higher than you declared is flagged, not failed: scored and drafted, with both quotes shown so you judge. The ad's own language never matters, only the role's.

06 · The agent patterns

Five habits that make prose behave like a system.

Script following

Read once, execute in order

A command is a numbered procedure. Reference files are read exactly once and stay in context; nothing is re-read "to be safe".

Fan-out

Parallel sub-agents, context inline

Scrape and rank dispatch work through the Agent tool with everything a sub-agent needs pasted into its prompt, so none of them re-reads the profile.

Separation

Drafter and reviewer

A fresh context cannot see the drafter's reasoning, so it cannot rationalize it. Edits return as exact strings and are applied mechanically.

State through tools

Query it, never load it

The seen-jobs file grows for the life of the workspace. A Python helper selects, sweeps and rewrites it so the backlog never enters the conversation.

Write-back

Same turn, or it is lost

Facts, follow-ups and outcomes are written the moment they are confirmed. The next session knows only what is on disk.

Portability

Thin pointers, one source

AGENTS.md points other harnesses at the same files. Portal CLIs use the portable Agent Skills format, so Codex or Gemini CLI discover them unchanged.

07 · Guardrails

Honest by construction, enforced by repetition.

The same rules appear in every command and every sub-agent prompt, because repetition is the only enforcement prose has.

The limit. All of this is instruction-level. Nothing sandboxes Claude away from fabricating or from an injected instruction; the rules hold because they are read. On an unfamiliar job board, skim what was fetched and written before you send.
  • Postings are untrusted data. No command follows text inside a posting, fetches a link found in one, or includes content because a posting asked.
  • Three-source grounding. A claim must be supported by the profile file, the master CV or CLAUDE.md. Reframed emphasis is fine; changed facts and escalated numbers are not.
  • Verified company claims. Reviewer research is a lead. Anything that lands in a letter or prep pack is re-fetched from a source located independently.
  • Respectful fetching. A 403 triggers a robots.txt check first. The browser-header retry runs only where the site permits it; otherwise search for the employer's own posting.
  • Verified output. PDFs are compiled, measured and read. Text layers are extracted and checked. "Looks fine in the source" is never accepted.
  • Gaps stay visible. A missing requirement is acknowledged with an honest bridge, never hidden and never keyword-stuffed.
08 · How JobPilot relates

Same methodology, different runtime.

The hosted platform compiles two of the nine methodology files into a Cloudflare Worker and enforces the gates in code. What it leaves out is deliberate: JobPilot drafts text, the local workflow produces the application.
