Usage explainer · platform/

JobPilot, explained.

A hosted agent that turns your profile into a reviewed shortlist of postings and, for the roles you approve, unverified text drafts. It searches, scores and writes. You decide. It never applies.

0applications submitted, ever
4agent stages per run
60searches per calendar month
1review gate before any draft
01 · The journey

One profile in. One reviewed shortlist out.

A run is a durable state machine. The agent advances one bounded step at a time, on a Cloudflare Durable Object alarm, so it survives a page reload, a closed laptop or a phone going to sleep. Your controls take effect at the next step boundary, up to about 25 seconds later.

02 · The workspace

Four pages. One durable account.

The web workspace and the iOS controller talk to the same Worker and the same per-user Durable Object, so a run started on one shows up on the other within a poll.

01
Mission control

Where the run lives

Status chip, four stats, the opportunity shortlist, the agent's activity timeline and the controls.

  • ＋ New search disabled while any run is unfinished
  • Pause · Resume · Retry · Cancel run by status
  • Finish review & prepare drafts during review
  • ↺ Inspect run timeline scrubber and audit export
02
Your profile

The facts the agent works from

Nine fields, validated in the browser and again by the Worker. Each run snapshots the profile, so later edits never alter a run in flight.

  • Country two uppercase letters
  • Work authorization drives the eligibility gate
  • Remote roles only enforced by the harness, not the model
03
Run history

The last 30 runs, decisions kept

Every run keeps its query, postings, evaluations, decisions and drafts. Selecting one reopens it in Mission control; historical runs offer no resume.

04
Membership

Stripe, at arm's length

View price & subscribe opens Stripe Checkout; once active it becomes Manage membership and opens the customer portal. No price is rendered in the app. Disabled in the local demo.

03 · Reading a match

Every score comes with its receipts.

An opportunity card is the unit of review. The model produces the score, gates and reason, but the harness checks that every evidence line is a verbatim quote from the posting and forces the score to zero on a failed gate.

  1. Title, company, locationFrom the source posting. The link opens the original only if it is a plain HTTPS URL.
  2. Fit score0 to 100 from the model. Any failed gate forces 0. Green when the role is draftable.
  3. ReasonThe model's one-paragraph rationale, escaped before rendering.
  4. Two gatesWork rights: PASS, FAIL or UNVERIFIED. Language: PASS, FAIL or FLAG. Silence in the posting is UNVERIFIED, never PASS.
  5. Evidence and gapsOne to eight quotes that must appear in the posting text, or the step fails and retries. Gaps are the model's honest unknowns.
  6. Prepare draftOnly offered when work rights are PASS and language is not FAIL. Everything else reads "Not cleared for drafting".

04 · Controls and limits

Bounded on purpose.

Every budget is reserved before the work that spends it: a run reserves a monthly search when it starts, a model call is counted before the request leaves. Retries spend from the same budgets.

60new runs per calendar month, reserved at start
8postings per run
20model calls per run
3attempts per step
1unfinished run per account
30runs kept in history
~25 smax wait for a pause or cancel
40 KBrequest body ceiling
ControlAvailable whenWhat happens
PauserunningCurrent step finishes, then the alarm is cleared. Nothing is spent while paused.
ResumepausedContinues from the stored stage and cursor. Needs an active membership in production and calls left in the 20-call budget.
RetryfailedClears the error and re-runs the step. The three-attempt cap for that step still applies.
Cancel runanything but completed cancelledEnds the run for good. It stays in history and can still be exported.
Finish reviewreviewRecords approved and rejected decisions, then drafts approved roles one per step. Zero approvals is valid: the run completes with no drafts.
05 · How it fits together

One Worker, one object per person.

Identity is verified at the edge, then every account operation is serialised inside that user's Durable Object. Model output can choose a query and write text; it cannot choose a URL to fetch, a tenant, a price or a send action.

Clients

Web and iOS use separate Auth0 applications but the same API audience, so both receive the same user subject and see the same durable state.

Core

The Worker authenticates and forwards; the Durable Object owns profile, runs, quota and the alarm that drives each bounded step. State and alarm commit in one transaction.

Audit

Timelines record activity, not wire bodies. The export seals into an OrcaReplay trace for inspection; byte-exact execution replay is out of scope.

06 · Two modes

The local demo is a fixture, not a fallback.

Demo mode only switches on when DEMO_MODE is true and the origin is localhost. Production has no bypass: a provider outage is a visible failed run, never a quiet fixture result.

Local demo · localhost:8797
  • Sign-inNone. Header reads LOCAL DEMO · FIXTURE DATA.
  • SearchTwo labelled fixture postings: one draftable, one that fails both gates.
  • ModelFixture text, recorded as demo-fixture in the timeline.
  • BillingDisabled. Checkout and portal APIs return 409.
  • StatePersists in .wrangler/state between restarts.
  • NetworkAPI refuses non-local hosts.
Production · your HTTPS origin
  • Sign-inAuth0 PKCE. Tokens expire normally; no refresh rotation.
  • SearchFreehire, up to 8 postings; source IDs seen in your last 30 runs are dropped.
  • ModelWorkers AI llama-3.3-70b-instruct-fp8-fast with schema-validated output.
  • BillingActive Stripe subscription required to start, resume, retry or review.
  • StateSQLite-backed Durable Objects on Cloudflare.
  • NetworkBrowser origin must equal APP_ORIGIN.
07 · API at a glance

Thirteen routes under /api.

Outside the demo every route except config, health and the webhook needs a bearer token. Responses are JSON and never cached. Repeating a run's request UUID returns the same run instead of reserving quota twice.

08 · The line it will not cross

You make the final call.

The agent's authority ends before employer contact. These are absent by design, not missing features.

  • Submitting an application
  • Messaging an employer
  • Auto-applying through a portal
  • Fetching a URL the model chose
  • Scheduled or recurring searches
  • Push notifications
  • Resume upload or parsing
  • In-app purchase on iOS
  • Claiming a company fact it did not verify
  • Falling back to fixtures in production
